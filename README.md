# Data Selection for ML Planning

Учебный проект системы отбора данных для обучения ML-планировщика движения.

## О проекте

Перед обучением модели сырые сцены необходимо преобразовать в формат обучающего
датасета. Такая подготовка требует времени и вычислительных ресурсов, поэтому
обрабатывать весь накопленный поток данных нецелесообразно.

Проект исследует, как выбирать ограниченный, разнообразный и информативный набор
сцен, который дает максимальное улучшение качества модели при заданном бюджете на
подготовку данных. Основные пользователи системы — ML-инженеры, формирующие датасеты
и обучающие модели планирования.

Предлагаемый процесс:

1. Получить метаданные доступных сцен из существующего индекса.
2. Исключить некорректные и уже обработанные сцены.
3. Оценить полезность кандидатов по качеству, редкости, новизне и разнообразию.
4. Сформировать версионированный список сцен в пределах вычислительного бюджета.
5. Передать выбранные сцены в существующий процесс подготовки данных.
6. Использовать результаты обучения и оценки модели как обратную связь для следующих
   циклов отбора.

## Цель первой итерации

Первая итерация должна дать воспроизводимый прототип пакетного отбора и методику его
проверки. Новый подход сравнивается со случайной и стратифицированной выборкой при
одинаковом бюджете на подготовку данных.

В итерацию входят:

- реестр кандидатов и история их обработки;
- случайный и стратифицированный baseline;
- ранжирование по доступным до подготовки признакам;
- ограничения на бюджет, разнообразие и число похожих сцен;
- объяснение причин выбора;
- offline-оценка и контур обратной связи.

Изменение существующих процессов индексирования, преобразования данных, обучения и
архитектуры планировщика в проект не входит.

## Настройка окружения

Требуется Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install pre-commit ruff
pre-commit install
```

Запуск всех проверок:

```bash
pre-commit run --all-files
ruff check .
ruff format --check .
```

В проекте используются [Ruff](https://docs.astral.sh/ruff/) для линтинга и
форматирования и [pre-commit](https://pre-commit.com/) для автоматического запуска
проверок.

## Данные и безопасность

Репозиторий содержит только публично безопасные конфигурации и документацию. Сырые
данные, обученные модели, результаты экспериментов, учетные данные, адреса закрытых
сервисов и локальные конфигурации не должны попадать в историю Git.

## Процесс разработки

Каждая домашняя работа выполняется в отдельной ветке `hw_n` и отправляется в `main`
через pull request. Перед отправкой необходимо запустить pre-commit и проверить diff на
наличие закрытой информации.
